Shell & Subprocess

“Execution Providers”

核心洞察:

Shell execution is a capability — local, remote, or sandboxed providers all share one interface.

Shell 执行是一种能力，本地、远程或沙箱提供者共享同一接口。这允许相同的工具在不同环境中工作。

架构流程图

提供者抽象

Shell 接口抽象执行环境。相同的 'bash' 工具无论在本地、远程还是沙箱中执行都有效——只有提供者改变。

沙箱集成

沙箱提供者可以限制文件系统访问、网络调用和进程生成。工具代码不变——安全性在提供者层面强制执行。

设计决策

文件系统和子进程提供者共享一个执行世界，因此将它们指向远程沙箱会移动一切。

安全性在提供者层面强制执行，而不是在工具代码中，实现所有工具的一致策略。

对比 Claude Code

DeepSeek Harness 有可插拔的 shell 提供者；Claude Code 有固定的本地执行。

深入设计决策

SKILL.md 作为知识单元

每个技能是一个 SKILL.md 文件，包含 YAML 前置元数据和 markdown 正文。这是最简单同时兼具人类可读和机器可解析的格式。

备选方案: JSON 或纯 YAML 对机器更友好，但人类编写和维护更困难。带前置元数据的 Markdown 平衡了两种需求。

三级优先级加载

技能按优先级加载：项目技能优先，然后是个人技能，最后是内置技能。同名的高优先级技能会覆盖低优先级技能，允许在不修改基础技能的情况下进行定制。

备选方案: 扁平的技能目录更简单，但无法定制。优先级链允许用户覆盖任何技能而无需 fork。
