Capability Seams

“Definition → Provider → Consumer”

核心洞察:

A capability seam comprises Service Definition, Service Provider, and Consumer — swapping one provider changes the whole product.

能力接缝遵循三角色模式：服务定义声明接口，服务提供者实现它，消费者使用它。替换一个提供者就能改变整个产品。

架构流程图

为什么是三个角色？

分离定义、实现和消费允许各自独立演进。你可以在不影响消费者的情况下更改提供者，或者在不修改提供者的情况下添加新的消费者。

提供者替换

接缝的力量在于提供者替换。将 shell 提供者指向远程沙箱，Bash、PTY 和 LSP 都会随之移动。无需代码更改。

设计决策

一个包可以组合角色，但单独一个角色不是接缝。添加能力意味着设计所有三个角色。

文件系统和子进程提供者共享一个执行世界，因此将它们指向远程沙箱会使 Bash、PTY 和 LSP 随之移动。

对比 Claude Code

DeepSeek Harness 有正式的能力接缝；Claude Code 有隐式提供者。

深入设计决策

分类优先的调度

任务在执行前按分类归类，每种分类映射到针对该类型工作优化的 agent 配置。模型从不看到路由逻辑。

备选方案: 单个通用 agent 可以处理所有事情，但针对不同领域的专业化配置能产生更好的结果。

分类是可插拔的

通过插件配置可以添加新分类，无需修改核心系统。每个分类指定了模型、温度、工具和系统提示词覆盖。

备选方案: 硬编码的分类更简单，但限制了可扩展性。插件定义的分类保持核心稳定，同时允许无限的专业化。
